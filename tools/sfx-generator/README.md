# sfx-generator

Процедурний генератор звуку для Android TV застосунку про кіно.
Усе синтезується з нуля — жодних семплів, жодних ліцензій.

- `uisfx.py` — вихідний набір UI-звуків (моно, сухо). Лишився як є.
- `dsp.py` — синтез-рушій: стерео, згортковий реверб, шимер, циклічний синтез.
- `tvsfx.py` — 19 UI-звуків + 4 амбієнт-петлі для Android TV.
- `check.py` — контроль якості готових файлів.

## Запуск

```bash
uv sync                          # створює .venv і ставить numpy/scipy/soundfile
uv run tvsfx.py -o out           # усе: ~6 секунд, 3.7 МБ
uv run tvsfx.py -o out --ui      # лише UI
uv run tvsfx.py -o out --beds    # лише петлі
uv run tvsfx.py -o out --only play logo amb_home
uv run tvsfx.py -o out --demo    # demo.wav: бед + сценарій UI поверх нього
uv run check.py out              # клип, DC, моно-сумісність, стик петель
```

`--demo` — найкорисніший режим на етапі підбору: він зводить бед і UI разом,
з тими самими гейнами, що поїдуть у застосунок. Окремі файли балансу не покажуть.

## Що вийшло

**UI** — WAV PCM16 48 кГц, короткі стерео (дрібні тіки пишуться в моно):

| звук | коли | мс |
|---|---|---|
| `focus` | рух фокуса по постерах | 35 |
| `nav_edge` | упор у край ряду | 59 |
| `key_tap` | екранна клавіатура пошуку | 13 |
| `select` | вибір картки | 300 |
| `back` | назад | 280 |
| `open` / `close` | вхід у сторінку фільму і вихід | 850 / 500 |
| `play` / `pause` / `stop` | керування відтворенням | 1150 / 450 / 300 |
| `seek` / `volume` | перемотка, крок гучності | 24 / 16 |
| `toggle_on` / `toggle_off` | перемикачі, «до перегляду» | 200 |
| `error` | помилка | 598 |
| `notice` | нова серія, рекомендація | 1400 |
| `download_done` | завантаження завершено | 1300 |
| `paired` | приставку прив'язано до акаунта по QR | 1050 |
| `whoosh` | перехід між екранами | 700 |
| `logo` | сплеш при старті | 4000 |

**Амбієнт** — OGG Vorbis 48 кГц стерео, безшовні петлі:

| петля | екран | с | КБ |
|---|---|---|---|
| `amb_home` | головний, Am add9 — тепло і нейтрально | 30 | 409 |
| `amb_details` | сторінка фільму, Dm7 — нижче й темніше | 24 | 317 |
| `amb_search` | пошук, Fmaj7#11 — світліше й прозоріше | 20 | 277 |
| `amb_player_idle` | пауза плеєра — майже порожньо | 32 | 403 |

`manifest.json` віддає для кожного файлу тривалість, канали, пік, LUFS
і рекомендований `gain` — ієрархію гучності всередині набору.

## Специфікація міксу

Беди зведені по **LUFS** (ITU-R BS.1770), а не по RMS. Це не формальність:
повносмуговий RMS міряв би переважно саб, і петля з великим низом виглядала б
гучною за цифрою, тихо зникаючи на реальному телевізорі.

- беди: −33…−37 LUFS, пік не вище −22 dBFS
- UI: пік −3 dBFS (`logo`) … −21 dBFS (`volume`)
- у демо-міксі кожна UI-подія стоїть на 6–21 дБ над бедом **у своїй смузі**

Окремо перевірено, що переживе вбудований динамік телевізора (він нижче
~150 Гц не грає нічого): жоден бед не втрачає більше 7 дБ. Тримається це на
`exciter` — саб отримує гармонічну «тінь» у середині, і вухо добудовує
основний тон там, де фізично його немає. Без цього беди губили 15–18 дБ
і для більшості людей просто не існували б.

## Android TV

**UI — SoundPool.** Він тримає розтиснуті семпли в пам'яті, тому затримка
мінімальна. Формат саме WAV PCM16 — це те, що SoundPool читає найдешевше.

```kotlin
val attrs = AudioAttributes.Builder()
    .setUsage(AudioAttributes.USAGE_ASSISTANCE_SONIFICATION)
    .setContentType(AudioAttributes.CONTENT_TYPE_SONIFICATION)
    .build()
val pool = SoundPool.Builder().setMaxStreams(6).setAudioAttributes(attrs).build()
// gain беремо з manifest.json — він задає ієрархію набору
pool.play(ids["focus"]!!, 0.35f, 0.35f, 0 /*priority*/, 0 /*loop*/, 1f)
```

**Петлі — AudioTrack у MODE_STATIC.** Тільки він дає посемпльно точний цикл:
`setLoopPoints` виконується апаратно, без повторного запуску декодера.
`MediaPlayer.setLooping` і `REPEAT_MODE_ONE` в ExoPlayer сюди не годяться —
вони дають мікропаузу, і вся робота над стиком піде намарно.

```kotlin
// OGG треба один раз розтиснути в PCM (MediaExtractor + MediaCodec)
val track = AudioTrack.Builder()
    .setAudioAttributes(attrs)
    .setAudioFormat(AudioFormat.Builder()
        .setEncoding(AudioFormat.ENCODING_PCM_16BIT)
        .setSampleRate(48000)
        .setChannelMask(AudioFormat.CHANNEL_OUT_STEREO).build())
    .setBufferSizeInBytes(pcm.size)
    .setTransferMode(AudioTrack.MODE_STATIC)
    .build()
track.write(pcm, 0, pcm.size)
track.setLoopPoints(0, pcm.size / 4, -1)   // -1 = нескінченно
track.play()
```

Ціна — оперативна пам'ять: 30 с стерео PCM16 це 5.8 МБ. Якщо тісно, беріть
коротші петлі (`amb_search` на 20 с — 3.8 МБ) або тримайте розтиснутим
лише активний бед.

**Чого не робити:**

- Не запитувати audio focus під бед. Людина може слухати музику з іншого
  застосунку — фонове гудіння вашого лаунчера не має її переривати.
  Навпаки: слухайте чужий focus і глушіть бед, коли його забрали.
- Не грати `focus` частіше ніж раз на ~50 мс. На швидкому скролі по постерах
  без обмеження виходить кулеметна черга.
- Не ігнорувати системний перемикач звуків інтерфейсу
  (`Settings.System.SOUND_EFFECTS_ENABLED`) — на ТВ його вимикають часто.
- Не тримати бед під час відтворення відео. Заглушіть його рампою за 300–400 мс
  через `track.setVolume()`, а не різко.

## Підкрутити під себе

Тембр набору живе у трьох місцях `tvsfx.py`:

- `_SPACES` — розміри залів. Збільште `decay` у `cinema` — і `play`/`logo`
  стануть масштабнішими.
- аргументи `bed()` — `sub_amt` і `warmth` тримають вагу, `dark`/`bright`
  задають діапазон руху фільтра, `air_amt` — кількість повітря,
  `loud` — місце петлі в міксі.
- акорди в `a_home()` / `a_details()` / `a_search()` / `a_player_idle()`.
  Частоти можна писати як завгодно: `snap()` сам притягне їх до сітки петлі.

Після будь-якої зміни ганяйте `check.py` — він ловить клип, фазові проблеми
в моно і, головне, розрив на стику петлі.
